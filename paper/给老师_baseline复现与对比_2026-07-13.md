# 本周进展：Baseline 复现 + 同片段对比 + 创新点首战告捷（2026-07-13）

老师好，按您上周的意见（**先联系作者，不行再自己改；口径桥接和名单照现在的来**），这几天我们完成了三件事：①主对照（NeurIPS'25 Zero-Shot STVG）**复现闭环**；②第一版「同片段、同口径」对比；③**主攻创新点（时序选择器）第一轮实验成功，超过了该 SOTA**。汇报如下。

## 一、复现闭环：我们的部署验证是正确的

上次汇报时我们只能跑出 m_vIoU≈0.08，与论文差距大。这次排查发现是**我们自己加的一个数据过滤补丁引发了"预测↔标注错位"**（它的评测按位置序号配对，过滤使位置平移）。撤掉后：

| | m_vIoU | vIoU@0.3 | vIoU@0.5 |
|---|---|---|---|
| **我们复现（base 档，n=300）** | **0.221** | **0.361** | 0.134 |
| 他人复现（其 GitHub issue #4，全量） | 0.207 | 0.314 | 0.132 |
| 论文报告（完整方法） | 0.236 | 0.368 | 0.155 |

**结论**：与他人复现一致、离论文完整方法差距很小——部署正确。
另外两点如实说明：① 其论文完整方法（DSTH/focus 档）的官方代码有参数不匹配的 bug 跑不起来，我们已在其仓库提了 [issue #5](https://github.com/zaiquanyang/LLaVA_Next_STVG/issues/5)（含精确定位与修法），等作者回复；② 但从数字看 **base 档只比完整方法低约 2 分**（0.21 vs 0.236），并非"弱化版稻草人"，用它对比是有意义的，我们会在论文中如实标注这一点。

## 二、首个同片段对比（同一批 HC-STVG clip、同一关键帧联合口径）

把它的预测（时空管）按之前您认可的桥接方式换算到我们的关键帧口径（时刻命中 ∧ 框 IoU 达标），在**完全相同的 282 个 clip** 上对比（其时段中点取整对结果敏感，故 floor/ceil 两种取法都报，防止口径偏袒）：

| 方法 | 时间召回 | acc@0.3（联合） | acc@0.5 | 选对时刻时 IoU |
|---|---|---|---|---|
| NeurIPS'25 baseline（floor / ceil） | **0.642** / 0.667 | **0.447** / 0.443 | 0.394 / 0.390 | 0.532 / 0.518 |
| **我们（单次前向，免调优）** | 0.557 | 0.433 | **0.411** | **0.613** |

**诚实读法**：
1. **总体相当**：宽阈值（acc@0.3）它略高，严阈值（acc@0.5）我们反超，"选对时刻时框的质量"我们明显更高（0.613 vs 0.532）；
2. **成本差一个量级**：它每个样本要做梯度式 test-time tuning，我们是免调优单次前向；
3. 差距来源清晰：我们弱在**时间召回**（0.557 vs 0.642）——这与我们此前量化出的"时序选帧是主瓶颈"（oracle 0.787）完全一致，**正是我们下一步创新点（时序选择器）要解决的**，叙事自洽；
4. 如实标注：它的原生任务是"整条时空管"，桥接到关键帧口径对它略有折损；论文中两套口径的数字都会给全。

## 三、创新点首战：两阶段时序选择器超过 SOTA（今天最重要的结果）

按您认可的主攻方向（时序选择器），我们提出**两阶段选帧**：**第一阶段**让 Qwen3-VL 看整段视频的 10 帧抽稀网格，粗定位"动作发生在哪个时段"（MLLM 的时序理解远强于 CLIP 逐帧打分）；**第二阶段**只在该时段内用 CLIP 物体条件打分精选关键帧。另做了一个轻量改进作消融：在打分里加"动作短语"通道（E1）。HC-STVG test 300 条、与之前完全同口径：

| 选帧策略 | 时间召回 | acc@0.3（联合） | acc@0.5 |
|---|---|---|---|
| E0 基线（物体条件选帧，上周汇报的） | 0.557 | 0.433 | 0.411 |
| E1 = E0 + 动作短语通道 | 0.613 | 0.497 | 0.477 |
| **E2 = 两阶段（Qwen 粗定位→段内精选）** | **0.717** | **0.570** | **0.543** |
| （参照）NeurIPS'25 baseline，同批 clip | 0.642 | 0.447 | 0.394 |
| （参照）时间 oracle 上界 | 1.0 | 0.787 | — |

**怎么读**：
1. **两个改进都有效且单调**（0.433→0.497→0.570），E2 最强；"选对时刻时框的质量"三组基本不变（≈0.63）——**增益全部来自"选对时刻"**，消融干净；
2. **E2 超过 NeurIPS'25 SOTA 约 12 个绝对点**（0.570 vs 0.447），且我们仍是免调优单次前向；E1 单独也已超过它；
3. 对照 oracle（0.787），瓶颈差距已从 0.35 缩到 0.22——后续还有提升空间（更细的网格、迭代细化等）。
4. 照例所有数字经独立重算复核；结果与脚本在公开仓 demo_2026-07-13/。

## 四、novelty 双查结果（本轮顺带做的，想让您知道）

按惯例我们对论文的"空缺声明"做了一轮对抗性双查（两个独立 AI 互不通气找反例）。**发现一个必须正视的先例**：**X-VILA**（NVIDIA，2024，any-to-any 模型）已能"视频输入→生成图像输出"，且有视觉一致性模块；NExT-GPT（ICML'24）架构上同理。

**处理**：我们已把论文声明从"没人做过视频→生成图"**改窄**为可守住的完整合取——"**问题驱动的显式时空定位 + 可验证的关键帧忠实生成（有协议有指标）+ 长式图文交错回答 + 配套基准**"，这个合取查遍 any-to-any / 统一模型 / M²RAG 系 / 视频摘要系后仍无先行工作（X-VILA 无定位、无忠实性协议、无交错长答案、无基准）。相关引用（X-VILA/NExT-GPT/Emu3.5）已加入论文。**这样改完，novelty 声明更窄但更硬，不会被审稿人一枪打死。**
